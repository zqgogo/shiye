## 怎么读这张表

- **证据**列只写可复跑的东西：`npm run verify:pN` 的具体断言、`npm test` 的用例名，或人工走查记录。没有证据支撑的一律不算通过。
- 状态分四种：
  - **已覆盖**：有断言，且最近一次执行通过；
  - **部分覆盖**：主路径有断言，但清单里的某个限定词没有对应用例（表中写明缺什么）；
  - **未验证**：依赖本机以外的东西（真机、真实 AI 服务），一律不勾；
  - **阻塞**：外部条件不具备，代码也没做，不在本轮范围。
- 所有断言名都能在 `.verify/reports/*.json` 的 `steps[].step` 里搜到；单测名在 `npm test` 的 verbose 输出里。

最近一次执行：Chrome 156 无头模式，`verify:browser` + `verify:import` + `verify:p1`～`verify:p6` + `verify:a11y` 共 **262 项全部通过**（按各报告 `steps` 计：41+16+37+40+45+36+31+16；P0 主库验证是结构化报告、不含 step 列表。阶段文档里的条数取自当时那轮脚本，脚本迭代后有个位数差异），`npm test` **79 项通过**，`npm run typecheck` 通过。

## 只能人工做的两件事

> 完整的人工清单见 [人工测试手册](../manual-test.md)（19 项，含右键菜单、划词、导入边界、恢复替换与记录表）。这里只记自动化完全替不了的两条。

1. **P6.4 真机**：工作台「数据」页导出可搜索 HTML，传到手机浏览器，用分类 + 关键词组合筛选，记录机型、系统、浏览器版本与结果。自动化只能代替到 375 宽渲染这一步。
2. **读屏播报**：焦点落点、`aria-modal`、错误提示的朗读顺序，需要 VoiceOver / NVDA 实听。本轮只断言了 DOM 与计算样式。

## 复跑

```bash
npm install
npm run verify        # typecheck + 79 项单测 + build
npm run verify:all    # 加上 9 个浏览器回归脚本，共 262 项
```

单跑某一阶段用 `npm run verify:p4` 这类；报告统一写到 `.verify/reports/`，不进版本库。浏览器验证依赖本机 Chrome 或 Edge，`SHIYE_CHROME` / `SHIYE_EDGE` 可指定可执行文件，`P0_BROWSER=edge` 可换浏览器。
