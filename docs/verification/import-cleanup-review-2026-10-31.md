# 导入收藏夹与清理功能专项复核

日期：2026-10-31。检查基线：`develop`，`99ca63b`。本文是验证证据；任务进度统一在 [ROADMAP](../ROADMAP.md) 维护。

## 结论

此前补的基础功能确实已实现：HTML 默认进入收藏库，提供原目录到已有分类的映射，支持撤销导入、清空待看、清空全部收藏以及指定分类/未分类。P9 的剩余任务是增强这些能力，并非表示基础功能未交付。

| 用户场景 | 当前实现与核查结果 |
| --- | --- |
| HTML 导入不再全进待看 | `capture:file` 默认 `library`，由粘贴模式切换到文件模式也设为 `library`；实际导入后待看与完成历史不变 |
| 导入时保留分类 | 解析并保留原目录，用户映射到已有分类后实际写入 `categoryId`；本次两个目录分别映射 A/B，均正确入库。不会自动复制目录树或创建分类，未映射仍是未分类 |
| 刚导错就撤销 | 结果页可撤销本批新增；本次撤销移除 2 条，原有 2 条收藏（包括本文件的重复项）保留，之后可立即重导同一 HTML |
| 关闭结果页后撤销 | 数据与备份 → 最近导入提供入口；同提交 P3 浏览器回归已验证。当前只展示最近 20 批 |
| 避免撤销覆盖后续修改 | 专项单测确认导入后改过的保留、待看批次撤销不碰收藏、同一批不能重复撤销 |
| 全部清空 | 收藏与其墓碑归零，包括回收站；分类、设置、待看及完成历史保持。不是重置整个应用 |
| 按分类范围清空 | 分类 A 的正常项和回收站项一并清除，只清相关墓碑；分类 B、未分类、分类实体及队列保留。取消确认不会写库，切换范围会清除旧确认状态 |
| 清空未分类 | 只清无分类的收藏，有分类的 B 保留 |
| 清空待看 | 只清 pending 队列，完成历史与收藏不动 |

## 已有功能的边界与剩余增强

1. **现有“筛选清空”支持分类与未分类范围。** 关键词搜索页没有清空匹配集按钮；按本批次、原始目录、站点、关键词组合选择并处理全部匹配，仍是 P9.2/P9.3 设计任务。
2. **“撤销导入”不等于“撤销清空”。** 现有彻底清空是硬删除，不能一键恢复；P9.4 的清理前本机快照尚未实现。误清只能依赖事先备份，替换恢复的安全副本不能当作已有清理快照。
3. **撤销详情与历史仍有缺口。** 结果页已有常驻移除/保留/缺失数量，最近导入页主要通过提示反馈；批次不持久保存完整撤销计数与保留原因，也不提供旧批次分页检索。这些是 P9.1 的增强范围。
4. **旧验证脚本已同步（2026-10-31 补）。** `scripts/verify-p0-import.mjs` 原先断言「默认目标为待看」，在当前正确的默认收藏行为下失败，使 `verify:all` 无法全绿。现已改为断言「默认目标为收藏库」，并保留「切到待看 → 切回收藏库」两次重算断言，覆盖切换目标会重新去重、重算统计的行为；该脚本随后 42 项全通过。默认目标没有、也不应被改回待看。

本次仅补充核查材料和规划状态，未更改导入或清理产品逻辑。浏览器原生右键、正常网页划词、手机真机及读屏仍按人工清单另行验收。
