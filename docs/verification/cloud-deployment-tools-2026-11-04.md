# v0.2 预览 3：自有 Cloudflare 部署工具与镜像续传

日期：2026-11-04。用户明确要求先准备部署工具，尚未部署自己的后端。本轮没有登录用户账号、创建云端资源或上传真实收藏。

## 已实现

- `cloud:prepare / doctor / login / deploy / verify`：本地随机独立项目、两份应用凭据和私有配置，部署前检查，账号选择，D1 查重/创建，迁移，Worker/Assets 部署，secret 哈希设置，在线无记录验证。已运行本机 prepare + doctor，未输出原始凭据，私有文件均被 Git 忽略。
- 部署中断阶段持久记录；先查询同名 D1，避免创建成功丢响应后重复创建；绑定过账号/项目/库不会被自动切换。只接受本次 CLI 输出确认的 Worker 地址，不向过时缓存地址发送凭据。
- 后端增加发布者专用上传状态与取消接口。状态只返回分片摘要，不暴露未发布内容；只读令牌不能用。取消未发布上传不影响 active 镜像，重复取消幂等，不能误删已经发布的镜像。
- 本机镜像快照、进度与执行权持久化：大快照不可变、小状态单独更新，单页面执行，失效确认拒绝，快照绑定本机身份及后端身份/地址；发布凭据仍只在页面内存。
- 刷新续接先确认服务器分片哈希，只补剩余片；发布响应丢失后可只查 active 编号确认结果；没有自动重试或后台上传。
- 逐片检查当前投影和隐私，发布前完整复核；新版本清除旧版本。取消暂存与清空镜像分别明确确认。备份不带队列，恢复/本机身份切换会清掉旧队列。
- Cloudflare 设置页新增三步部署帮助、快照恢复、分片进度、分页发送预览、取消和发布结果核对。AI 仍直接访问模型服务，和上述部署完全独立。

## 保留的边界

这仍是 S1 私有只读镜像，未实现 S2 双向同步。云端部署流程已交付并由模拟 CLI 验证，本机准备与官方本地运行时已验证，真实账号部署须用户自行登录后运行。真实域名、免费 CPU 额度、手机网络与 Safari 真机仍不能据此标记完成。

## 原生浏览器请求修复

用户实际连接时遇到 `Failed to execute 'fetch' on 'Window': Illegal invocation`。原因是 MirrorClient 将原生 fetch 保存在实例上并通过实例调用，导致浏览器收到错误的接收对象。默认请求函数现在绑定到 globalThis；注入测试请求的接口保持不变。

原浏览器测试以 JavaScript 替换 fetch，未覆盖原生函数的接收对象约束。现增加保留原生 fetch、仅在浏览器网络层提供本地模拟响应的连接测试：修复前失败，修复后通过。`verify:cloud-publication` 现共 14 项通过；另通过类型检查、10 项后端测试及扩展构建。没有修改或重新部署用户云端资源。
