## 2. 新增的页面级回归脚本

`scripts/verify-p2.mjs`（`npm run verify:p2`），沿用 P0/P1 的启动与断言方式，只在真实扩展页面里操作 UI，断言一律回读 IndexedDB 主库。覆盖：

- P2.1：七个基础页面直接进入、空状态、分类选择在新建时生效。
- P2.2：待看完成、撤销完成、转收藏（同一事务内新增收藏并完成待看）。
- P2.3：打开详情不自动标已读；标记已读只改未读位不动分类。
- P2.4：已分类未读、未分类已读、已有收藏加入待看、长标题（300 字符可存 / 320 字符被拒）、重复收藏的常驻失败提示。
- P2.5：分类创建、置顶与取消置顶、单条恢复未读、全部标记已读、软删除与恢复保留分类、清理完成历史。
- P2.6：未保存离开提醒的三种触发路径、字段长度提示、墓碑转收藏的显式选择。

`scripts/lib/launch-extension.mjs` 的 `readMainLibrary` 增加 `pinned` 字段，供置顶断言使用；该改动对 P0/P1 脚本只是多返回一个字段，不影响原有断言。

### 环境限制

这两轮由用户在普通终端执行。AI 会话内的自动化环境启动 Chrome 时会被系统代码签名校验拦下：

```text
[sandbox] 命令被沙箱拦截：
  .../com.google.Chrome.code_sign_clone/.../Google Chrome (file-delete)
```

浏览器进程因此起不来，puppeteer 拿不到实例。这不是脚本逻辑问题，人工终端执行不受影响。后续阶段的浏览器回归同样需要在普通终端跑，命令：

```bash
npm run build
npm run verify:p2          # 只跑 P2（36 项）
npm run verify:all         # P0 + P0.4 + P1 + P2 全量回归
```

原始 JSON 写在 `.verify/reports/`（不入库）。

## 5. 风险与限制

- 未保存提醒是「拦截 + 确认」，不做草稿持久化：刷新页面或关闭标签页仍会丢草稿，与 v1a 范围内「不引入跨会话草稿」的取舍一致。
- 墓碑恢复 + 完成待看是两个事务（先恢复收藏，再完成队列）。中间失败时收藏已恢复、队列仍是 pending，用户可再次点「完成」收尾；不新建第二条收藏这一条不被破坏。
- 最近打开 15 条的用例通过原生 IndexedDB 写入 16 条脱敏样本，只验证页面筛选与截断，不替代 P4.5 对「最近打开统计口径」的验收。
- 首轮 30 项未覆盖 P2.1 的视觉一致性（暖白、绿色、分组导航与设计稿的对照）；该项属于整体交付的人工走查，不写进自动化。
