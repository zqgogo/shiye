## 2. 数据风险

按「会不会丢数据」排序，前三条是必须让用户知道的。

**① 卸载扩展 = 删除全部数据。** 主库是扩展 origin 下的 IndexedDB，移除扩展时浏览器会连库一起删，没有回收站。装之前、删之前都请先导出备份。目前**没有自动备份**，也不打算在 v1a 做。

**② 换机器/换 profile，数据不跟过去。** 扩展 ID 变了，origin 就变了，库是另一个。唯一通路是导出 JSON 再恢复。恢复时面板会提示「主库身份已切换」，此时旧环境还在写就会分叉——先把旧的那份停掉。

**③ 替换式恢复会清空当前主库。** 代码在替换前会自动导出一份安全备份并展示时间与条数，但**这份文件在你浏览器的下载目录里**，不是库内快照；如果下载被拦、磁盘满、或者事后把文件删了，就没有第二份了。合并恢复没有这个风险，只是不会覆盖本机已有改动。

**④ 本地专用条目默认不进备份。** 不勾选「包含本地专用条目」，换机后这些条目就没了（它们本来就不该随文件走）。勾选等于把它们写进明文 JSON，自己权衡。

**⑤ 手机快照是明文。** 任何拿到 HTML 的人都能读到标题、链接、备注（如果开了备注开关）。设计上排除了本地专用与已删除条目，但**没有密码**，分享前先想清楚。

**⑥ 墓碑只防本机的鬼。** 删除会写墓碑，同一份库里的旧备份恢复时不会复活已删条目。但如果恢复的是一份**没有墓碑的旧备份**（例如 v1a 之前导出的），界面只能提示「删除语义可能失效」，无法阻止已删条目回来。

**⑦ 双设备同时写会分叉。** 没有同步机制，两台机器各写各的，只能靠备份合并。合并按 ID 去重、保留本机版本，不会静默覆盖，但也不解决「两边都改过同一条」的冲突。

**⑧ AI 材料包是手动复制出去的。** 手动交接需要你自己把材料粘到外部 AI，粘出去的内容受对方隐私政策约束，扩展无法回收。材料包里已排除 `localOnly` 与 `aiBlocked` 条目，并只带白名单字段。

## 3. 行为上的已知限制

- 标题上限 300 字符，超限实时提示并拒绝保存；备注与摘录同理。
- 单批导入上限 1000 条、书签文件 3 MB，超出直接拒绝，不静默截断。
- 资料选择一次最多 60 条进入提问包，超出会明确提示，不会自动截断，也不会因为「全选」就发送。
- 分类置顶最多 8 个；删除分类必须先选迁移目标，收藏一条不少。
- 「最近打开」只保留最新 15 个不同收藏。
- 工作台与弹窗共享同一份库，多标签页通过广播同步；**不同浏览器 profile 之间不同步**。
