# v0.2：快速访问、内置 AI 与自有 Cloudflare

日期：2026-11-04。承接用户实测通过的导入工作台版本。此文是本轮开发方案，完成情况只记录在 ROADMAP。

## 版本目标与顺序

1. **快捷入口**：插件弹窗顶部可切换「收藏当前页／快速访问」，记住上次页签；保持当前收集表单。快速访问直接搜索、按层级分类浏览、查看置顶／最近打开／待看，点击直接打开网址，不先去工作台。不覆盖浏览器新标签页，不改变书签数据。每页 20 条，跨页和空状态齐全；外站图标不自动请求。切回时保留尚未保存的收集表单。
2. **P7 内置 AI**：自配 DeepSeek 或 Chat Completions 服务；独立配置、模型列表、合成文本／JSON 测试，修改配置使测试失效，通过后主动开启。Key 只在可信工作台内存，离开或刷新清除；不放到 Cloudflare、备份、URL 或内容脚本。问答和整理保留手动通道，增加「检查材料→确认发送→回答／建议→人工应用」。问答依据本地所选材料，保留编号来源；整理复用现有校验、应用和撤销，预览 1 保留单批交接；预览 2 补齐全范围分片计划、手动重试和刷新续接，实际范围与边界见分片整理实施记录。
3. **S1 Cloudflare**：用户自己的 Workers + D1，HTTPS 服务地址和应用级发布凭据可配；扩展不索取 Cloudflare 管理 token。首次连接只握手，预览记录和确认后才发布。分块上传不可变 generation，完整校验后 CAS 原子发布，失败继续保留旧镜像。手机同域只读页面可登录、搜索、分类和打开链接。发布凭据与只读凭据分离，移动页只接受只读登录，写接口不接受 cookie。
4. **S2 双向同步**：独立后续里程碑，不混进 S1。新增本地写入同事务 outbox、固定 opId 回执、shadow/cursor 原子提交、多页执行租约、身份/epoch 守卫、冲突 UI，再开放双向开关。旧备份合并不能复用为同步更新算法。

快速访问是本机即时入口，不依赖云端和 AI；删除项不显示，本地专用项仍能在本机访问。搜索在本地执行，不请求远程 favicon；仅用户点击时打开对应网页。最近打开来自现有记录字段，不新增全浏览历史权限。

工作台设置新增「内置 AI」「Cloudflare 记录镜像」独立入口，分别显示发送内容、目标地址和最后操作结果。连接配置可以保存非敏感项；当前轮凭据采用页面内存，不承诺重启后免输。

## S1 协议与存储

- `/v1/info`：鉴权握手，返回 protocol/serverId/libraryId/epoch/revision/activeGeneration；客户端发布请求绑定全部身份。
- `/v1/generations`：声明 UUID、baseRevision、分块数、条数和分块哈希汇总值，创建 staging。
- `/v1/generations/:id/chunks/:index`：不可变写入，重复相同内容幂等，不同内容拒绝。
- `/v1/generations/:id/publish`：校验每片、计数、重复主键、类别引用和哈希，在 D1 batch 中 CAS 切换 active。旧发布者基线和旧 epoch 拒绝，重试已激活版本可核对成功。不允许未完整上传的内容替换旧镜像。
- `/v1/mirror`：只返回当前发布版本的一片，客户端绑定 generation 读取，切换中止后重读，避免混合多个快照。
- `/v1/session`：手机只读 token 换同域 HttpOnly/Secure/SameSite=Strict cookie；退出清 cookie。所有私有响应 no-store，token 不进入地址。
- 云端只保存白名单收藏、待看、必要分类/标签；不上传备注/摘录、来源历史、隐私标记、AI 任务、Key、应用日志、导入暂存或派生索引。本地专用和已删除收藏排除；分类与标签只取实际引用及祖先。
- S1 采用整份替换镜像表达删除和转私密，只有再次成功发布后云端才撤回；离线时旧镜像仍存在。提供清空云镜像入口。旧发布版本数据随切换清理，未完成上传按期限淘汰。
- 服务端校验 schema、字节数、分片上限、父级引用、循环及重复 ID。D1 SQL 使用绑定参数，鉴权主体决定唯一库。S1 不实现任意公开分享、多用户协作和云端 AI 代理。

## 验收与发布门槛

快捷入口需浏览器实测切换、表单保留、搜索、分页、直接打开链接和最近记录。P7 需模拟网络核查配置失效、取消、超时、截断、旧材料拒绝、隐私发送前复核；真实 DeepSeek 凭据不在仓库，没有用户配置时不得宣称真实服务验收完成。S1 需本地实际 SQLite SQL 测试（含并发 CAS、上传中断、篡改与身份隔离）、协议集成和构建。真实 Cloudflare 部署需用户账号；无部署证据只标本地通过。

Safari 沿用已有正式支持目标：统一浏览器适配层，提供 macOS 包装/安装说明及能力矩阵。未完成签名与真机证据时明确未发布，iOS 只读网页与 macOS 扩展分开验收。

官方实现依据（2026-11-04 复核）：[D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/)、[D1 限制](https://developers.cloudflare.com/d1/platform/limits/)、[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。不承诺免费额度足够所有库，也不启用模型工具或搜索。

| S1-A 云端验收 | 用户部署模板到自有账号，实测一个完整库、网络中断、重复发布和手机登录；测最终 CPU、配额与网络可达性 | 真实 D1 条数和字段对齐；转私密及清空后云端查不到旧记录；iOS Safari 真机证据 |

| S2-A 同事务 outbox | 在所有写入口同事务记录不可变 opId、entityType、baseVersion、localRevision、payloadHash、service identity；覆盖弹窗、菜单、导入、撤回、AI、恢复、分类移动和删除 | 人为中断不能出现“本地已写但队列丢失”；ACK 只确认所发送的那个版本 |
| S2-B push/pull 存储 | D1 单事务分配全局版本、验证 epoch/CAS、保存 opId 回执；pull 数据、shadow、冲突和 cursor 在本地同事务提交 | 丢 ACK 重试幂等；同库分页无漏项；不同账号/epoch/后端的旧操作不重放 |
| S2-C 冲突与撤回 | 私密化产生远端撤回操作而非单纯不上传；墓碑保留、防止普通更新复活；冲突保留两份并显示裁决；完整依赖图落库后推进 cursor | 离线删除/改隐私、同条并发编辑、分类依赖跨页到达都不丢数据；未裁决不悄悄覆盖 |
| S2-D 调度与恢复 | 数据库持久租约选唯一执行者，指数退避只用于可幂等同步；恢复/换库先暂停，用户选择重新连接或作为新库发布 | 多标签页/后台休眠后可重入；本地备份恢复不擅自 reset 其他设备 |

S2 本地存储单独增加 `sync_outbox`、`sync_shadow`、`sync_conflicts`、`sync_state`，与现有本地 revision 和 AI 材料隔离。服务端增加按身份分区的 `records`、全局版本分配和 `op_receipts`。先完成内存传输双设备契约测试，再接 D1；不能只因有同名记录就跳过更新，也不能无条件覆盖。S1 数据迁入 S2 使用显式迁移步骤，不让本轮只读 API 被误用于编辑同步。
