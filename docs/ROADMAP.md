## 给执行 AI 的工作方式

1. 先检查 Git 分支、工作区改动和适用的 `AGENTS.md`；阅读本规划、目标阶段和相关技术说明。保留已有改动。
2. 从当前阶段第一个未完成的任务开始。一次处理一个可验证的小任务；完成后记录改动、实际验证命令或操作、结果、风险和下一项。只按用户授权的范围继续。
3. 使用脱敏数据和 fixture。不要读取用户真实收藏、接入真实密钥或部署云资源，除非用户明确提供并授权。需要设备、供应商或凭据的验证明确记录为待验证。
4. 不能把构建成功、模拟结果、桌面缩窗或静态检查当作真实浏览器、手机或服务商验证。失败要保留证据并修复或记录阻塞原因。
5. 若资料冲突，产品与技术实现说明优先作为需求依据；记录冲突和决定。技术说明第 22 节采用 P0–P6 的合并编号，任务书细分为 P0–P7：本规划采用后者，P4–P5 对应技术说明 P4，P6 对应技术说明 P5，P7 对应技术说明 P6；任务范围不因此删减。
6. 扩展是唯一可编辑主库的入口；普通网页不能被默认为与扩展共享 IndexedDB。AI 默认关闭，手动交接和内置通道共用隐私、授权、校验和事务规则。v1b 单独安排。
7. 接手时确认资料包可读。若只拿到 Git 仓库而没有同级 `resource`，先取得需求资料，不能凭任务标题推测字段或协议。资料包正文中的部分配套文件名仍写 v2_0，本目录实际提供 v2_1，读取实际文件并记录该文案差异。
8. 任务勾选表示该任务的实现与验收均完成。外部设备或凭据暂不可用时，记录具体阻塞任务，继续不依赖它的已授权工作；不得把整个阶段标完成。阶段状态为阻塞时，也要注明可继续的独立任务。

自动测试、类型检查与构建按阶段维护，接入持续集成以验证干净检出的安装和构建；真实浏览器、手机及服务商证据独立记录。测试样例引用时写明来源与含义：技术说明与 `test-cases.json` 的 `A02` 定义不同，不能仅凭相同编号认定同一用例通过。

## P0 · 最小工程与关键能力验证

目标：确认后续实现的基础可行，并形成可重复的开发环境。结果填写 [P0.md](P0.md)。

- [x] **P0.1 工程准备**：检查 Node 版本及项目结构，选定兼容的 React、TypeScript、Vite、Dexie 等依赖与测试工具，加入锁文件和最小构建、类型检查、测试命令；记录运行要求。只搭最小验证入口。
- [x] **P0.2 扩展与主库**：搭建最小 MV3 扩展、popup 和工作台，验证它们在同一扩展 origin 访问同一 IndexedDB 主库；记录 Chrome / Edge 版本、加载方式及主库位置。
- [x] **P0.3 重启验证**：写入脱敏样例，关闭并重开浏览器及扩展后读取；记录实际步骤、结果与限制，验证 MV3 生命周期相关假设。
- [x] **P0.4 文件与手机验证**：用脱敏多层书签 HTML 和损坏输入验证文件读取及层级解析方案；验证最小手机只读 HTML 的可打开性。记录实际设备和浏览器；设备不可用时保留待验证项。
- [x] **P0.5 结论**：记录通过、失败、未测、调整和后续方案。供应商真实请求在用户选择供应商并授权凭据后验证；没有凭据时独立列为待验证，不阻塞与其无关的本地基础工作。
- [x] **P0.6 扩展边界与复现**：确认电脑安装策略、扩展 CSP、独立脚本及打包方案；明确 `activeTab`、所选文字、右键菜单和按需主机权限的用途，禁止常驻全网页扫描。规定消息来源及运行时输入校验，content script 不得读取凭据或发任意代理请求。补充干净安装、构建和加载步骤及最小持续集成检查。

P0 的未验证项：手动「加载已解压的扩展程序」流程需用户首次安装时确认；右键菜单实际点击与所选文字读取未在自动化中触发；手机真机与 AI 供应商请求未验证。以上均为环境/外部条件限制，不影响 P0 其余结论，已列入 [P0.md](P0.md)。

进入 P1 的条件：工程命令可复现，扩展共享主库及重启持久化有实际证据；文件与手机验证的结果或阻塞已记录，影响后续设计的问题已处理或明确限制。真实手机验证仍是 P6 交付门槛。

## P1 · 核心规则、数据模型与持久仓库

- [x] **P1.1 领域模型**：按技术说明及 `reference/domain.ts` 建立正式类型与运行时校验，覆盖待看、收藏、分类、标签、设置、批次、日志和墓碑；移除价值等级及其理由。
- [x] **P1.2 纯规则**：实现保守 URL 规范化、字段授权、隐私过滤和版本规则；区分 `originalUrl` 与 `canonicalUrl`。
- [x] **P1.3 持久化**：设计并实现 Dexie schema、索引、迁移与 Repository；通过 application 用例访问数据，避免 UI 直接操作数据库。
- [x] **P1.4 事务与验证**：覆盖重复创建、版本冲突、事务回滚、未分类索引、旧数据迁移与关闭重开；索引及授权不能依赖不适用的 boolean/null 键或宽泛的 `Partial`。
- [x] **P1.5 数据保护基础**：集中字段和容量限制，校验文件、消息、AI 输入而不仅是 TypeScript 类型；按技术说明定义旧格式迁移及默认未读规则。当前没有生产旧库，使用有版本说明的 fixture 演练。迁移前须具备最低可恢复备份能力；迁移失败停止编辑并保留原库，不通过删库重建掩盖错误。
- [x] **P1.6 并发与删除规则**：用多窗口并发验证事务内 URL 去重、稳定 ID、版本比较和墓碑；明确软删除、显式恢复、正文清理及最小墓碑保留规则。网络、文件解析和 hash 计算放在事务外，派生搜索索引可重建。

完成证据：可复现测试覆盖上述失败路径与数据完整性，迁移结果和浏览器重启验证有记录。

## P2 · 工作台、待看与收藏

- [ ] **P2.1 页面骨架**：依据设计稿实现暖白、绿色和分组导航，以及首页、待看、收件箱、未分类、全部收藏、最近打开、详情、回收站的基础页面。
- [ ] **P2.2 待看与收藏**：实现待看新增、完成、历史和撤销；转收藏须在同一事务中新增并完成，重复时展示已有收藏。
- [ ] **P2.3 状态与详情**：实现收藏编辑、取消、锁定、隐私、版本保护与最近打开 15 条；未读与分类状态独立，打开、分类或 AI 处理不自动标已读。
- [ ] **P2.4 页面验证**：验证已分类未读、未分类已读、已有收藏加入待看、完成撤销、空状态、长标题与失败提示。
- [ ] **P2.5 日常操作补齐**：实现基础分类创建和选择、收藏置顶/取消、单条与全部已读及恢复未读、收藏软删除/恢复，以及用户主动清理待看完成历史；不自动永久清理。已完成待看再次加入时恢复 pending 并更新加入时间；引用收藏被删除后队列仍保留 URL 和标题。
- [ ] **P2.6 编辑与删除冲突**：区分来源描述、AI 用途、人工备注和主动保存的选中文字；实现未保存离开提醒和字段长度提示。相同 URL 存在删除记录时，转收藏须让用户明确选择恢复或新建；普通导入不能绕过墓碑。恢复收藏保留原分类与未读状态，失效分类引用按明确规则处理。

完成证据：关键操作在扩展工作台中持久化，转换事务、重复与失败路径通过验证。

## P5 · 手动 AI 交接与安全应用

- [ ] **P5.1 交接数据**：实现输入结构、字段预览、指纹、策略版本、批次与编号映射的本地持久化。
- [ ] **P5.2 导入和预览**：严格校验 JSON、编号和字段，展示可应用、拒绝和过期原因；刷新后可续接本机批次，缺映射或换主库明确拒绝。
- [ ] **P5.3 应用与撤销**：事务内重查版本、隐私、锁定和引用；仅授权分类、标签和 AI 用途，不修改未读、待看或人工备注；逐项报告结果，撤销不覆盖后续修改。
- [ ] **P5.4 异常验证**：覆盖重复、过期、未知编号、非法字段、恶意字符串、部分成功与撤销冲突。
- [ ] **P5.5 手动提问通道**：问题与资料选择生成可预览、有字符上限的提问包；实际发送字段经用户确认，剪贴板失败提供可复制文本。回答在外部 AI 查看，不强制导回；整理结果按本阶段的严格 JSON 导入流程处理，两类操作不混用。
- [ ] **P5.6 策略和快照规则**：提供分类策略的编辑、版本和整理范围选择；`inputHash` 使用规范 JSON，覆盖实际输入、人工分类/标签、选中文字和锁定，排除最近打开及新生成的 AI 输出。发送前重查 `localOnly`/`aiBlocked`，两类都排除，本版 AI 仅处理收藏。策略改变、删除或隐私变化使旧结果失效；模型建议的新分类须用户单独创建再校验。应用日志、已接受基线与版本原子更新；未应用不得标成已分析完成。

完成证据：可追溯批次、严格校验、预览、应用和撤销均有测试；隐私内容不进入交接材料。

## P6 · 备份、恢复与手机快照

- [ ] **P6.1 备份**：从一致的逻辑快照导出完整 JSON，包含待看及状态、收藏、分类、标签、设置、策略和墓碑，排除凭据。
- [ ] **P6.2 恢复**：预览并区分合并和替换；替换前备份并展示时间与数量，验证版本错误、失败回退和恢复后的深度数据一致性。
- [ ] **P6.3 手机只读快照**：仅导出允许展示的正式收藏，支持分类和关键词组合筛选，过滤私密和删除内容，安全渲染并提供无脚本基础列表。
- [ ] **P6.4 设备验证**：在实际手机浏览器打开快照，记录设备、浏览器、操作与结果；检查注入、隐私及文件使用限制。
- [ ] **P6.5 导出隐私和主库身份**：本地专用数据须用户明确勾选才进入可携带 JSON；手机快照默认排除 `localOnly`，备注和选中文字单独选择，`aiBlocked` 不等于禁止用户普通导出。快照标导出时间且不自动更新。恢复区分空环境、合并和替换，未知新版拒绝、旧版显式迁移；无墓碑旧备份提示删除语义限制。替换或换浏览器配置后旧 AI 映射失效，并提示唯一主库的迁移与停止旧库写入步骤。

完成证据：恢复后完整数据核对通过，实际手机验证有记录；下载发起不等同于确认文件已保存。

## P7 · 可选内置 AI

- [ ] **P7.1 配置与启用**：默认关闭；配置变更使测试失效，只有真实测试成功且用户主动启用后才可调用。凭据留在可信上下文，不进入备份、日志、同步、URL 或 content script。
- [ ] **P7.2 适配器与两类操作**：实现用户选定供应商的 adapter、直接问答和进入校验预览的直接整理；复用手动通道的隐私、白名单、锁定和版本保护。
- [ ] **P7.3 异步与故障**：处理取消、限流、鉴权失败、页面关闭与结果未知，保留问题、选择和草稿；不自动换模型或重试计费。
- [ ] **P7.4 真实验证**：用户提供并授权凭据后，以不含收藏的测试请求验证权限及服务，再验证直接问答和整理。缺凭据时标待验证，不把 mock 标成可用。
- [ ] **P7.5 网络、引用和凭据细节**：按目标供应商官方文档确认端点、模型、认证、输出格式、上下文和超时；不假定所有兼容服务支持相同参数。默认 HTTPS，拒绝 URL 内凭据和跨 origin 重定向；本地 HTTP 需显式设置和验证。凭据默认仅 session 且限可信上下文，跨重启保存另行设计；撤销主机权限使启用失效。回答引用绑定当次快照，未知引用标无效；区分权限、配额、限流、超时和未知结果。工作台关闭后恢复草稿但不自动重放请求。

完成证据：可单独关闭模块且不影响本地功能；真实供应商验证、密钥隔离及异常恢复结果有记录。
