# 书签导入改版建议

日期：2026-11-04。状态：已实施核心工作台、目录层级、分页、暂存、移动和导入专用 AI，实际交付与验证见 [实施记录](verification/bookmark-import-workbench-2026-11-04.md)。后文保留设计依据，完整交付边界以实施记录为准。本次补充多次导入、可选 AI 辅助整理，以及分类与记录拖拽要求。依据实际书签截图及当前 `capture.tsx`、导入解析器、分类模型、导入事务和撤回实现整理。

## 1. 当前问题

截图中 898 条书签、839 条可新增，导入页要求逐个原目录选择已有分类。目录映射表与书签明细表均全量渲染，明细依靠内部滚动，没有复用现有分页组件。导入自动建分类尚未提供。

当前 Category 只有名称，没有父分类。分类名称全局去重，上限 60 字符。书签原目录是用于追溯的字符串。因此自动建分类需要同时处理目录层级、同名目录、名称长度与重复链接，不能直接把每个末级目录名插入现有分类表。

## 2. 两种导入方式

### 默认方式：先独立保存，稍后整理

解析后默认选择“先独立保存”。确认按钮显示“保存为待整理导入（839 条）”。保存后立即进入这次导入的专属页面，按原目录树浏览、搜索、分页，可整批撤回或按目录处理。提供“按原目录加入收藏库”和“选择部分加入收藏库”。

这次导入以独立的持久化暂存记录保存，刷新或关闭浏览器后可以继续。记录进入“待整理导入”，正式收藏计数、收件箱、主库搜索、AI 资料选择及普通收藏导出仅接收已经加入收藏库的记录。数据页明确提示仍有多少暂存书签，并提供独立备份/恢复入口，避免用户误以为完整收藏备份已经包含它们。

待整理导入页保留原目录结构。用户可以折叠目录、按一个父目录选择整个子树、移除不需要的目录，确定需要后再加入收藏库。父目录选择显示含子目录的总条数。

暂存时保留文件中合法链接的目录归属，并标记与正式收藏库重复、回收站冲突、文件内重复及无效记录。正式入库时按当时数据库状态重新去重，不能复用几天前的预览结论。

### 可选方式：按原目录直接加入收藏库

选择“按原目录直接导入收藏库”后，系统生成分类创建与复用计划，自动把书签放入对应分类。通常无需逐目录操作。原有手工映射收拢到“调整分类”，用于少数例外。

确认区展示“将新增 839 条收藏、新建 N 个分类、复用 M 个分类、跳过重复 K 条”。实际数字按最终选择计算，示例不作为固定值。

直接导入与暂存后加入收藏库使用同一个入库计划与事务实现。整批入库完成后直接展示本批结果，提供“查看本批”“撤回本次加入”。

### 已有收藏时的加入位置

“是否先暂存”和“正式加入到哪里”是两个连续选择。直接导入跳过暂存步骤，正式加入仍需明确目录落点。暂存后加入时使用相同的落点选项。

| 收藏库情况 | 建议默认落点 | 用户可改选 |
| --- | --- | --- |
| 首次使用，收藏与分类都为空 | 按原目录放在根级 | 放入新的分类组 |
| 已有收藏或分类 | 放入新的分类组 | 合并到现有目录 |

选择正式加入时展示推荐值及理由，用户确认后执行。已明确选择的落点保持到本次计划结束。正式库在预览后发生变化时重新校验，范围或分类落点需要改变则要求重新预览。

**放入新的分类组**：系统建议组名，例如“导入 · Safari · 2026-11-04”，允许修改。组下完整保留文件的原目录树。已有“工作 / 技术”，新文件中的“工作 / 技术”会放在“导入 · Safari · 2026-11-04 / 工作 / 技术”。旧分类保持当前位置。组名与当前父节点下已有分类重名时建议带序号的新名称，预览明确显示。新组与普通正式分类具有相同的搜索、编辑及备份能力，导入批次记录另外保留来源与撤回关系。

**合并到现有目录**：默认目标为收藏库根级，也可选择一个已有分类作为目标父目录。按结构逐层匹配，同一父节点下同名的目录复用，缺少的目录创建。若现有“工作 / 技术 / iOS”，新文件包含“工作 / 技术 / iOS”和“工作 / 技术 / Android”，前者复用，后者只新增缺少的 Android。层级不同或名称仅相似的目录分别保留。可以在预览中明确映射到指定目录，系统不通过模糊匹配擅自合并。

建议预览目录树并列显示“原路径 → 最终路径”，标出复用/新建。只列需调整的映射例外，支持分页、按路径搜索及父目录子树选择。去掉浏览器外层目录等操作需要重新计算最终路径与碰撞结果。

### 多次导入的重复与来源

- 全库按规范化网址去重，两种正式落点使用同样的规则。选择新分类组仍需检查已有收藏和删除标记。
- 已有链接保留原记录与原分类。预览写“已在 工作 / 技术，跳过”，新文件期望的目录位置保存在本次导入明细中，便于查看差异。批次记录区分原文件条目、跳过项和本次实际新增项，撤回只作用于实际新增项。
- 同链接希望改分类时，提供单独的显式“调整已有收藏分类”操作及确认流程，先展示受影响记录。普通导入不把重复项自动搬到新目录。
- 回收站中的同网址列为冲突，提供明确恢复原记录的选择。新增导入不得绕过原删除决定。
- 再导入同一份文件时，主要显示新增、重复及冲突数量。最终没有实际新增记录时，不创建新的空分类组或空目录。
- 本次加入的收藏属于其原始创建批次。后续文件中的重复项可以在后续批次明细中查看，但后续撤回不能删除或撤回之前批次的收藏。

正式写入前，分类名称与父节点关系在事务内重新检查。另一页面并发创建了同一路径时复用合法目标。目标父节点已被移走、改名或删除导致确认路径变化时中止本次计划并提示重新预览，避免写入用户未确认的位置。

## 3. 原目录与分类规则

- 正式分类增加父分类关系，以完整结构确定目录身份。同一父目录下同名分类可复用，不同父目录下的同名分类分别保留。例如“工作 / 工具”和“生活 / 工具”互不合并。
- 暂存区保留独立的原目录树。解析结果需提供目录节点 ID、父节点与路径片段。现有 `sourceFolder` 字符串继续用于来源显示，目录身份使用结构化数据，避免目录名含 `/` 时产生歧义。
- 分类名称使用单层目录名称，路径在面包屑与分类选择器中展示。单层名称超过 60 字符时，预览集中列出可编辑建议名，保留原始名称，禁止静默截断造成碰撞。
- “收藏夹栏”“其他书签”等浏览器根目录默认保留。提供显式“去掉浏览器最外层目录”选项，预览展示去掉后的路径及可能合并的分类，用户确认后应用。
- 默认仅创建包含最终实际新增收藏的目录及必要祖先。全是重复、无效或未勾选记录的目录不生成空分类。
- 文件同一链接出现在多个目录时，正式库仍保持现有单收藏去重规则。预览标出这些多目录重复，默认使用文件顺序中的首次有效出现，其余目录归属作为来源保留。未来若要一条收藏属于多个分类，另行设计数据模型。
- 已有收藏按当前去重规则跳过，保留原来的标题、分类、备注与隐私。回收站冲突单独列出，恢复原收藏需要用户明确选择。

分类层级会影响分类管理、改名与移动、搜索、选择器、统计、备份恢复和旧库迁移，需要同批适配。旧分类迁移为根级分类。旧版备份读取后按根级处理，新备份携带父关系与格式版本。

## 4. 大批量预览的交互

预览顶部保留总量统计、导入方式与确认按钮，主要区域使用“左侧目录树、右侧书签列表”。目录树默认折叠，标注总量/可新增/已选数量，点击父目录查看整个子树。

目录调整表与书签明细分别分页，复用当前每页 20–50 条设置。两者各有搜索，目录按路径搜索，书签按标题或网址搜索。状态补齐“需确认”筛选，截图里的 1 条需确认应能直接定位。提供“仅看异常”，集中处理重复、无效及待确认项。

全选按钮明确写“选中当前目录全部可新增 N 条”或“只选本页 N 条”，选择跨页保留。全局待写入数量始终可见。翻页与搜索只改变视图。改导入方式时保留仍合法的勾选，必须重算的变化清楚说明。

目录计数与书签筛选共用一份完整数据，分页只改变展示。创建分类按最终选中且事务内可新增的记录计算。浏览器目录映射作为高级调整，默认自动生成计划。

## 5. 数据与撤回

- 暂存解析结果与正式收藏采用独立存储。暂存记录保存原目录、原始行号、稳定编号、解析警告及入库进度。
- 暂存进入正式库时，分类创建/复用、收藏写入、来源与编号映射、批次状态更新放在同一个事务内，失败整体回滚。重新提交同一批次使用稳定操作 ID，避免重复入库。
- 部分加入后，对每条暂存记录标记已加入、重复跳过、待处理或失败。关闭页面后继续时，已成功的记录保持进度，剩余记录重新预检。
- 保存暂存文件不会改动正式收藏。加入正式库后沿用当前撤回保护，已被用户修改的收藏保留，撤回数量如实报告。
- 自动创建的分类记录所属导入批次。撤回后仅清理本批创建、仍为空、未被用户修改、没有其他内容或子分类引用的分类。已有分类与被其他记录使用的分类保留。
- 硬删除继续使用清理快照。快照应包含恢复所需的目录结构及分类依赖，恢复时遵守当前冲突跳过规则，父分类失效时给出明确落点。
- 当前单批最多 10000 条、文件 30 MB（2026-11-04 已扩容），暂存 JSON 上限 100 MB。以后继续扩大容量时，以逻辑导入组跟踪多个执行分块，明确部分成功、重试及按组撤回的行为。

## 6. AI 辅助整理

### 入口与作用

导入预览、待整理导入页提供“AI 帮我整理”，正式收藏页提供“整理所选记录”。AI 是用户主动开启的可选环节，基础导入、目录映射、分页和拖拽先独立交付。此前 AI 推迟到下一大版本的安排，在本方案中增加这项导入整理需求，实际接入作为后续独立实施阶段。

| 场景 | AI 可以建议的内容 | 用户确认内容 |
| --- | --- | --- |
| 原目录太深或太碎 | 简化层级、整理名称、按主题重新分组 | 原目录与建议目录的差异、移动记录数量 |
| 新文件加入已有收藏 | 将新目录映射到已有分类，或新建缺少的分类 | 完整目标路径、新建与复用数量 |
| 少量无目录或标题不明确 | 基于已授权标题、站点与原目录提出归类 | 每条去向与建议理由，无法判断时留待整理 |
| 疑似语义重复 | 列出可能重复的记录及理由 | 人工选择保留、跳过或调整，普通导入仍按规范化网址判重 |

默认保留原目录，用户选择“优化这份目录结构”后 AI 才提出重组方案。已有库只向 AI 提供用户同意参考的目标分类字典。已有收藏的搬动另列“已有记录调整”，默认不勾选。新导入项和已有记录在预览中分别计数，用户可以逐目录或逐条采用建议。

### 发送与应用

- 沿用既定的自配 AI 方案，DeepSeek 优先，通过统一适配层支持经过验证的兼容服务。配置入口由设置统一管理。已有手动材料包渠道可以先接入新计划协议，直连渠道在供应商适配完成后复用同一协议。
- 点击后先展示发送范围、字段、分批数量及服务商。默认材料为所选标题、站点、原目录与授权目标分类。完整网址含路径/查询参数、备注、摘录及网页正文分别征求授权。AI 请求会把所选材料发送给用户配置的供应商。
- 已有记录沿用 `localOnly`、`aiBlocked` 与字段锁定约束，发送前与应用事务内分别复核。分类字典也需排除未经同意的敏感路径。暂存记录增加相应隐私与 AI 排除设置。父目录含被排除子项时，按实际允许记录生成材料，不能通过目录统计或样例泄露被排除内容。
- AI 只返回受限的整理计划，包含批次/计划 ID、临时目录 ID、父子关系、目标分类 ID、记录 ID、建议动作与理由。新增目录、目录移动与合并通过新的整理计划校验，现有仅允许改 categoryId/tagIds/aiPurpose 的 AI 字段白名单继续用于原场景。
- 本地校验引用、层级深度、循环、同父同名碰撞、范围外 ID 和版本。模型返回的内容属于数据，不能触发任意数据库操作或文件指令。标题、目录名中的指令性文字也按材料处理。
- 几百上千条按输入预算分批，先形成目录方案，再按统一目录编号归类记录。应用前合并、去重并验证完整覆盖率，显示“已分析 800 / 898，失败 98”。失败分片可重试，用户可以明确选择只采用已成功部分。
- 点击“采用建议”后先更新导入草稿，正式入库仍走最终确认。正式库已有记录的调整需单独确认并写操作日志。应用前记录或目录被改动时，将对应建议标为过期，提示重算，保留用户最新修改。

### AI 与手动调整的衔接

预览使用“原目录 → 当前计划目录”显示差异，并标记“原样保留 / AI 建议 / 手动调整”。用户拖拽后，以手动选择为当前草稿，提供“固定此项”防止后续 AI 重算覆盖。未固定但已修改的计划也必须经过差异确认才能采用新版建议。

保留原始导入目录作为来源，整理动作修改当前目标目录。提供“恢复原目录方案”“撤销这次整理建议”，与“撤回已经入库的本批收藏”分别标明作用范围。

## 7. 分类与记录拖拽

### 基础行为

| 拖动对象与位置 | 结果 |
| --- | --- |
| 分类拖到另一分类内部 | 连同子分类移动，分类 ID 稳定，所含收藏继续引用原分类 |
| 分类拖到同级节点之间 | 调整同级手动顺序 |
| 分类拖到根级落点 | 变为根分类，保留子树 |
| 收藏拖到目标分类 | 更改归属，原始导入来源保留 |
| 多条选中收藏拖到分类 | 处理明确显示的全部所选记录，显示跨页数量 |
| 同分类内拖到记录之间 | 在“手动排序”模式下调整顺序 |
| 暂存记录拖到另一暂存目录 | 调整本次导入草稿的归属 |
| 暂存记录拖到正式分类 | 打开“加入收藏库”确认，重新去重及核对分类，确认后执行 |
| 待看拖到收藏分类 | 打开已有“转入收藏”确认，核对重复和回收站冲突后执行 |

目录层级、手动顺序与分页一起实现。目标节点中心与前后插入线使用不同高亮，拖动时持续显示目标完整路径和处理数量。悬停折叠分类可展开，边缘可滚动。拖拽手柄与复选框、链接点击区域分开，批量已选 N 条时拖动已选行表示移动 N 条，拖动未选行只移动该行并显示“1 条”。

名称相同的分类移动到同一父节点时，先显示“重命名后移动 / 合并目录”选择。合并需预览子树及重名处理，对用户确认后的最终计划一次执行。仅路径相似时不自动合并。分类拖到自己或自身后代时显示禁止落点，事务内再次校验循环与最大层级。删除、清空与恢复仍使用现有明确入口。

### 分页、排序与替代操作

- 记录列表增加“手动排序”。标题、时间、最近打开、搜索相关度排序时，仍可拖向分类改变归属，列表内顺序拖拽仅在切换为手动排序后启用。
- 分类与记录采用持久化顺序字段，例如同级 rank。新记录默认追加至目标列表尾部，原有数据按明确的稳定顺序补齐。分类排序按父分类作用域保存，记录顺序按其当前分类保存。快照恢复保留可用原顺序，冲突时追加并提示。
- 分页条数设置与跨页勾选沿用现有规则。目标分类树持续可见，长距离移动也可通过“移动到…”搜索目标分类完成。跨页精确排序提供“移到本分类最前/最后”和“移动到指定记录前/后”，避免要求用户跨页拖动不可见的行。
- 全部收藏、搜索结果和父目录子树混合视图中的记录归属以单条记录 categoryId 为准，移动时展示实际旧路径及目标路径。混合视图首期提供跨分类拖动，手动排列在单一分类列表中进行。
- 提供“移动到…”、“上移/下移”、“提升一级”等按钮及键盘操作，触屏使用长按手柄并支持目标选择器。Chrome、Edge、macOS Safari 分别验证拖拽与回退操作。

### 保存、并发与撤销

拖动开始时记录实体版本及源位置。落点确定时冻结记录清单、目标分类和排序锚点，执行事务内复核。类别层级改变后核对祖先关系，移动记录时核对源归属、版本、目标有效性与排序版本。界面先显示移动反馈，写入失败时回退显示并保留错误原因。

分类移动、目录合并、批量跨分类移动与排序写入统一的组织操作日志，保存修改前后位置、涉及 ID 和操作后版本，成功后提供“撤销移动/撤销排序”。撤销仅作用于操作后未再次改变的实体，冲突逐条说明。目录合并涉及跨引用变更，执行与撤销都需保持子树关系一致，任一步失败整体回滚。合并属于影响范围较大的操作，先确认再提交。

AI 采用、手动拖拽、按钮移动共用组织操作用例与校验规则。正式目录变化会使依赖旧路径的导入预览或 AI 建议失效。恢复快照、备份迁移、后续同步也需携带父关系与手动顺序。

## 8. 实施顺序与验收

1. 先补当前导入页的目录映射分页、书签明细分页、目录/关键词筛选与需确认定位，立即改善现有大文件操作。
2. 补分类层级与结构化原目录，以及“按原目录自动建分类”的入库计划、事务和撤回规则。同时补分类/记录移动、手动顺序及拖拽入口。
3. 补持久化待整理导入区，接通“先独立保存”与“直接入库”两条路径，完成后将独立保存设为默认。
4. 接入 AI 整理计划预览，先贯通已有手动材料包渠道，再接自配 DeepSeek/兼容服务直连渠道。该阶段独立验收凭据、发送确认、隐私及分批失败恢复。

验收至少包括以下场景。

- 898 条书签导入，目录与书签均可分页，正常记录可一次确认，仅少数异常需要干预。
- 不同父目录下同名分类保持独立，同一路径可复用，长目录名及含 `/` 的目录名不会混淆。
- 已有“工作 / 技术 / iOS”时，选择合并只复用同路径分类，选择新分类组则在新组下创建原目录，原有分类位置保持一致。
- 第二份文件与第一份部分重复时，只新增缺少的链接。重导全重复文件时不留下空组，撤回第二次导入不影响第一批收藏。
- 两个页面同时导入相同目录时没有重复兄弟分类，目标父目录变化时旧确认失效。
- 默认暂存后重启浏览器仍可继续，正式库仅接收明确加入的记录。
- 暂存后正式库新增了相同链接，加入时重新判重，当前收藏与删除决定得到保留。
- 只选一个目录中的 200 条跨页入库，实际处理全部 200 条，其他目录保持原状态。
- 中途写入失败时分类与收藏共同回滚，重试后无重复记录和多余空分类。
- 部分入库、整批撤回、恢复清理快照后，目录、分类和批次关系一致。
- 旧库升级、旧备份恢复、新备份迁移均可回读分类关系。
- 分类跨父级移动、同级排序、记录单条/多条跨分类移动刷新后仍保留，父子目录不能形成循环。
- 相同父目录下重名移动明确选择重命名或合并，合并确认前可查看范围，失败后数据与目录共同回滚。
- 手动排序模式跨页操作保持稳定顺序，全选 200 条中含跨页条目时拖动按显示数量执行。
- 拖动期间另一标签页修改源记录或目标目录，旧落点计划失效或逐项跳过，撤销不覆盖后续修改。
- 暂存拖入正式分类、待看拖向分类均完成专门确认、去重及事务写入，待看转换后的收藏关系正确。
- AI 整理 898 条分片覆盖完整，失败分片可重试，范围外 ID、循环和无效分类引用均被拒绝。
- localOnly/aiBlocked 条目及未经授权的分类路径不出现在 AI 材料，发送前改隐私会重新过滤。
- AI 建议先预览再采用，手动固定的目录与记录保持用户归属，正式应用与撤销遵守版本保护。
