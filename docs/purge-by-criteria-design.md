# 按条件清理：设计讨论稿

版本：0.2。日期：2026-10-30。**未立项、未写码。**
需求依据：[导入撤回与批量清理：场景与设计说明](import-rollback-and-bulk-cleanup-design.md)（下称"场景说明"）。本文只负责把它的判据落成可实施的分层与接口。
0.1 版被该文件 §7 评审出九处问题，本版逐条修正，见 §7。

## 0. 一句话

优先顺序是：**退这次导入 → 清这批的一部分 → 清空一个明确范围**。通用条件面板是补充，不是"刚导错了"的必经入口。

## 1. 为什么不是逐条勾选

几百上千条时，勾选的成本高于重导。清理的单位必须是**条件命中的集合**：说清"我要清哪一类"，界面告诉你命中多少条，确认后一次处理。

## 2. 三层场景与当前状态

| 实际情况 | 首选动作 | 范围 | 状态 |
| --- | --- | --- | --- |
| 整份文件导错、导错目标 | 撤回这次导入，再选正确目标重导 | 本批实际新增 | 已实现；重导导航待增强 |
| 关页后才发现 | 数据与备份 → 最近导入 → 撤回 | 按文件名/时间/目标找批次 | 已实现；只列最近 20 批 |
| 文件大体对，某个目录/站点不要 | 查看本批 → 按目录/站点筛选 → 处理全部匹配 | 先限定批次再缩小 | **P9 优先补** |
| 只想清掉某一类 | 清空该分类 / 未分类 | 该分类下全部收藏 | 已实现；含之前已有的同类记录 |
| 待看整批是误导入 | 清空待看 | 当前 pending | 已实现；完成历史与收藏不动 |
| 整库都不要 | 彻底清空收藏库 | 全部收藏 + 回收站 + 删除标记 | 已实现；不等于整库重置 |

"清空收藏库"不清待看、分类、标签、设置与日志，界面与交接材料不得与"整库重置"混用。

## 3. P9 的第一期只做三件事

对应场景说明 §5。不做通用面板优先，避免为退一份文件先面对十几个开关。

| 编号 | 内容 | 为什么先做 |
| --- | --- | --- |
| P9.1 | **完善批次撤回**：执行前统计、执行后常驻结果、查看保留项、刷新后能找回、较旧批次可搜索分页 | 最短路径，覆盖大多数"刚导错了" |
| P9.2 | **查看本批记录**：按原始目录、站点、状态筛选；按钮写"处理全部匹配 N 条" | 文件大体对、只有一部分不要 |
| P9.3 | **从入口带入范围的清理**：批次/分类/待看页带入范围，高级面板再允许改范围 | 不默认全库搜同站点 |

**明确不做**：为了误导入一份文件，默认在全库范围按站点清理。范围必须从入口带上，改成全库要用户主动改。

上千条同样靠集合操作完成。预览可分页/虚拟列表，但**总命中数与被处理的范围必须完整**，不能只处理当前页。

**批次组**：单批导入上限 1000，若将来拆成多批，同一次逻辑导入记 `groupId`，撤回按组进行，不让用户猜是哪几批。

## 4. P9.1 批次撤回的缺口

现有 `undoBatch()` 已按 `importItems` 只处理本批新建项，原有重复记录不在撤回范围。缺的是"看得见、找得回、说得清"：

| 缺口 | 现状 | 要补 |
| --- | --- | --- |
| 执行前不知道会删多少 | 直接确认，事后才知道 removed/kept | 预览 `removed / kept / missing` 三类计数 |
| 不知道哪 20 条被保留、为什么 | 只有一句 toast | 常驻结果面板 + **查看保留项**（标题 + 原因） |
| 关闭页面后查不到结果 | 批次只存状态 `reverted` | 批次持久保存 `undoAt` 与 removed/kept/missing 及保留原因 |
| 较旧批次找不回 | `listBatches()` 固定 `limit(20)` | 分页/按文件名与时间搜索，不永久限于 20 批 |
| 重复撤回 | 已拦 `reverted` | 文案写明"同批只能撤一次"，不诱导重复点击处理保留项 |

保留原因要分得清：**导入后改过**（编辑/分类/标签/隐私/应用 AI/标已读）、**待看已完成或转收藏**、**已移入回收站**（软删本身递增版本）、**实体已不存在**（missing）。

两个必须守住的边界：

- 导入时的目录映射分类**不算**"后来改过"，本批初始 `localRevision` 仍是 1。
- 仅打开过网页不算改过（`lastOpenedAt` 不递增 `localRevision`），这类记录仍会被撤回——界面上应说明"看过 ≠ 改过"。

## 5. P9.2 查看本批与"处理全部匹配"

```text
本批：bookmarks.html · 今天 19:00 · 导入到收藏库
原 900 条：新增 780 · 重复/跳过 100 · 无效 20

筛选  目录 [全部 ▾]   站点 [全部 ▾]   状态 [未改过 / 全部 / 已改过]
匹配 512 条（未改过 498 · 已改过 14）
[ 处理全部匹配 512 条 ]   [ 撤回整批 ]
```

- "处理全部匹配"只处理命中集合，与当前页可见条数无关；分页只影响预览。
- 匹配集合在执行前冻结（§7.1 的预览令牌），执行中新增或改动的条目不静默纳入。
- 本批范围内默认动作是"退回这批新增"（硬删 + 清对应墓碑），因为这是抵消一次错误新增；是否允许"移入回收站"作为另一种选择，留待实施时确认（硬删才能立即重导同网址）。

## 6. P9.3 通用条件面板（第二期，不是入口）

从批次/分类/待看页带入范围后可改。条件叠加为"与"，留空即不限；不支持的条件**禁用并说明**，不静默忽略。

| 维度 | 取值 | 适用 |
| --- | --- | --- |
| 范围 | 收藏库 / 待看 / 两者（分别报数、分别动作） | 两者 |
| 批次 | `importBatches` + `source.importBatchId` | 两者 |
| 原始目录 | `source.originalFolder` | 两者 |
| 站点 | `canonicalUrl` 主机名 | 两者 |
| 来源时间 | 批次时间或 **`source.capturedAt`**，不用记录 `createdAt` | 两者 |
| 视角 | 正常列表 / 回收站 / 两者（**三态，不用布尔**） | 仅收藏 |
| 从没打开过 | `lastOpenedAt === null` | 仅收藏 |
| 没有分类 / 标签 / 备注和摘录 | 对应字段 | 仅收藏 |

动作分开展示，不混用一个"可恢复"的说法：

| 范围 | 动作 | 可恢复 |
| --- | --- | --- |
| 收藏 | 移入回收站 | 是 |
| 收藏 | 彻底删除并允许重导 | 否 |
| 待看 | 彻底删除 | 否（首期不补待看回收站） |

## 7. 上一版被评审出的九处问题与修正

| # | 原稿错在哪 | 修正 |
| --- | --- | --- |
| 1 | 写"执行时重新筛选"，会扩大范围：确认 200 条可能实删 260 条 | **预览令牌**：preview 冻结候选集合与截止时间；execute 校验令牌、范围、条件与版本，**新命中不自动加入**，要求重新预览 |
| 2 | 写"待看范围下忽略收藏专属条件" | **不支持就拒绝**，返回可读错误；忽略条件等于扩大删除范围 |
| 3 | 把 `localRevision > 1` 当通用免删 | 三档保护分开，见 §8；否则已分类、已读、已在回收站的记录永远清不掉 |
| 4 | 用一个 `includeTrash` 布尔 | 视角三态：正常 / 回收站 / 两者，语义不含糊 |
| 5 | 混合范围共用一个"移入回收站 231 条" | 收藏与待看分别展示数量与确认，待看不冒充可恢复 |
| 6 | 用 `createdAt` 当导入时间 | 读批次时间或 `source.capturedAt`；预览截止时间要冻结 |
| 7 | 批次与目录各自匹配，可能一条记录两半命中 | **同一条 `source` 行上同时成立**才算命中 |
| 8 | 确认框只显示活跃列表数，实删还含回收站与墓碑 | 拆出"正常 N · 回收站 M · 删除标记 K"，三项都与实删一致 |
| 9 | 写"10k 条几十毫秒"当保证 | 改为待实测：1k/10k × Chrome/Safari，测完写数；分块要说清部分完成与恢复 |

## 8. 保护模型：三档，不要合成一条

| 场景 | 是否因"被改过"而保留 | 说明 |
| --- | --- | --- |
| 撤回本批新增 | **是，强制** | 导入后的任何人工或模型决定都不该被一次"退回导入"抹掉 |
| 主动清理（用户说"我不要这些"） | **否**，默认不豁免 | 用户已在明确表达意图；`localRevision > 1` 不能再当免死金牌 |
| 预览后并发修改 | **是，跳过并报数** | 预览令牌内的版本比对，跳过后提示"已变化 N 条，请重新预览" |

这条区分是本次评审最重要的修正：**"退回一次新增"和"我主动不要这些旧数据"不能共用一个保护规则。**

## 9. 清理快照（替代"每次自动导出 JSON"）

场景说明 §6 定的默认值：**默认先在本机事务内保存清理快照，失败就停止硬删；下载是可选副本。**

- 独立表 `purgeSnapshots`：编号、时间、范围与条件摘要、被删条目完整快照、状态。
- 执行顺序在同一 `rw` 事务内：算候选 → 写快照 → 删除 → 标 `applied`；任一步失败整体回滚，不出现半清空。
- 与恢复用的安全副本 `SAFETY_COPY_PENDING` **互不覆盖**，两者是不同用途的副本。
- 默认只存本机，不下载、不上传云端；提供"导出这份快照"作为可选动作。
- 保留策略实施时定（最近 N 份或手动删），不无限增长。
- 快照里不能漏掉用户正要保护的本地专用数据，也不能把快照默认传云。

## 10. 数据层接口（修正版）

```ts
type Scope = 'library' | 'reading' | 'both';
type View = 'active' | 'trash' | 'both';

interface PurgeCriteria {
  scope: Scope;
  view?: View;              // 仅收藏；默认 active
  batchId?: Id;
  groupId?: Id;             // 批次组
  originalFolder?: string;
  host?: string;
  capturedBefore?: string;  // 来源时间，不是记录 createdAt
  neverOpened?: boolean;
  uncategorized?: boolean;
  untagged?: boolean;
  bare?: boolean;
}

interface PreviewToken {
  token: Id;
  frozenAt: string;
  counts: { active: number; trash: number; reading: number };
  sample: { id: Id; title: string; changed: boolean }[];
}

previewPurge(c: PurgeCriteria): Promise<PreviewToken>;
purgeByCriteria(c: PurgeCriteria, token: Id, mode: 'trash' | 'hard'): Promise<{
  removed: number; trashed: number; skippedChanged: number; snapshotId: Id;
}>;
```

一个纯谓词 `matchesPurgeCriteria(record, sources, criteria)` 供预览与执行共用，避免两套判断。执行时**在令牌范围内**核对，不是重新全库筛选。

## 11. 风险与代价

| 风险 | 缓解 |
| --- | --- |
| 预览与实删不一致 | 预览令牌 + 冻结集合 + 事务内版本核对，不一致就跳过并报数 |
| 误删已加工内容 | 撤回强制保留；主动清理靠预览展示"其中 N 条已改过" |
| 硬删不可恢复 | 默认动作是回收站；彻底删除单独确认；执行前写清理快照 |
| 快照与恢复副本混淆 | 分表、分编号、各自确认，互不覆盖 |
| 分类清空数量对不上（现存缺陷） | 见 open-issues ⑩：页面按活跃列表计数，仓储会连回收站一起删 |
| 待看无回收站 | 界面直说；首期不补，避免假的可恢复暗示 |
| 接入同步后 | 本地硬删不能当作同步协议；已上传的误导入仍需发出删除，防止另一设备带回 |

## 12. 验收

对齐场景说明 §8，逐条要能复跑：

1. 原有 100 条 + 新增 800 条，一键撤回后原有 100 条完整保留。
2. 编辑 10 条、完成待看 5 条：保留并逐类报数。
3. 文件内重复项只是跳过，撤回不删原有同网址收藏。
4. 导错到待看：撤回这批待看，不动收藏与别批待看。
5. 关闭结果页后仍能找到批次；部分保留结果可再次查看。
6. 本批 800 条、目录筛出 500 条：处理 500 条，不是当前页 50 条。
7. 预览后另一页面新增/修改：新命中不静默纳入，已改条目不被旧确认覆盖。
8. 同范围含正常与回收站：显示数量与实删一致；待看动作不冒充可恢复。
9. 快照失败或删除中途失败：不出现半清空，不覆盖旧安全副本。
10. 接入同步后，撤回/清空能传播删除，不因本地硬删立刻丢掉未确认的同步任务。

单测与浏览器断言在实施时按下表补：

| 层 | 条数 | 重点 |
| --- | --- | --- |
| 单测 | 约 10 | 令牌范围外不删、条件不支持即报错、三态视角、同 source 命中、计数一致、快照失败回滚 |
| `verify:p3` | 约 6 | 查看本批、处理全部匹配（非当前页）、保留项可查看、批次结果持久、数量一致 |
| 手册 | 3 分钟 | 故意导错 → 撤回 → 重导；本批内筛目录处理 |
